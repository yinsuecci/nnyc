# nn远程移动客户端

Android 和 iOS 共用 Flutter 通讯录。当前版本可导入桌面配置的公开字段、搜索设备、
复制设备 ID，并检查信令服务的 HTTPS 健康状态。连接不需要预先登记手机，也不需要手机设备令牌。
Windows 启用 `mobile_desktop` 并上线后，点击「手机连接码」。在手机通讯录选择该电脑，进入
「连接远程桌面」并输入 9 位连接码。码限该电脑使用，2 分钟失效，用一次或生成新码后旧码作废。
Windows 仍需选择仅查看或允许操控，并核对两端显示的指纹后点击确认，不用抄写第二个码。
会话只使用内存中的临时凭据。手机无需摄像头或麦克风权限；允许操控时可点击画面定位并左键单击，
退至后台主动断开。更新时须先更新信令服务，再更新两个客户端；旧手机登记不会被自动撤销。
本路径尚不支持移动文件传输、键盘或 TURN 中继。需在真机上验证蜂窝网与宽带之间的连通性。
Windows 用户可在批准手机邀请前勾选实验性单屏隐私共享。手机只在主机持续确认
遮挡及静音、且已渲染远端画面时显示确认状态；超过三秒未收到状态即撤回确认。

在连接前，可从设备连接页右上角选择隐私屏图片，裁剪或完整显示并保留本次草稿。
建立可操控的会话后点击「应用图片」。手机发送的是预览生成的 1280×720 PNG，
而非原始相册文件；Windows 显示预览并要求本地确认，保存前再次检查会话授权。
只读会话不提供此通道。草稿不写入磁盘；保存壁纸不表示物理屏幕已经遮挡。

信令服务配置 `stun_port`（合并部署使用 `NN_STUN_PORT`），并单独映射/放行相应 UDP 端口。
手机使用已认证信令服务报告的端口和同一主机名；Windows 在设备配置 `rtc_stun` 中指定相同服务。
STUN 返回映射地址不表示能够穿透所有 NAT。信令 TLS 证书必须受 iPhone 信任。

导入示例：`{"signaling":"https://signal.example.invalid","peers":{"office":""},"device_names":{"office":"办公室电脑"}}`。
默认仅在本次打开期间保留通讯录。导入时可选择在此设备记住服务地址、设备 ID 和显示名称；
应用重启后不会沿用旧在线状态。「更多选项 → 清除本机通讯录」移除本地副本，不更改服务端权限。
健康检查要求有效的受信任证书，不跟随重定向。

项目目录中运行 `flutter analyze` 和 `flutter test`；Android 测试包使用
`flutter build apk --debug`。正式 Android 签名从环境变量
`NN_ANDROID_KEYSTORE`、`NN_ANDROID_KEY_ALIAS`、`NN_ANDROID_STORE_PASSWORD`
和 `NN_ANDROID_KEY_PASSWORD` 读取，不使用调试密钥替代正式签名。
iOS 需在配置 Xcode 的 macOS 构建机编译，真机安装需要授权签名。

私有信令 CA：在仓库根目录运行
`python tools/export_phone_directory.py WINDOWS_PROFILE.json WINDOWS_DEVICE_ID phone.json`。
输入必须是已通过独立渠道确认的 Windows 配置；设备 ID 是被控电脑自己的 ID。
输出白名单只含 HTTPS 地址、电脑 ID、名称和可选的单张公开 DER 证书，不复制任何令牌或私钥。
手机导入后仅对该通讯录的信令请求使用这份信任，仍校验域名/IP 和有效期，不修改系统信任库。
切勿从未经验证的线上握手直接建立信任。更换私有 CA 后需重新导入。
