# nn远程

单机合并部署（`pilot_service.py`）的凭据格式见 `config.example.json`。
实际文件名为 `config.json`，只在服务器上生成，随运行目录只读挂载到
`/run/nn/config.json`。两个令牌应分别随机生成（推荐各 32 随机字节的十六进制编码）。
示例中的 `***` 无法用于启动。TLS 私钥单独挂载，不在此 JSON 中存放 SSH 密码。
更换凭据后需重启服务，并同步更新相应管理客户端或节点的认证配置。

## 管理后台与多服务器中继

新增 `/admin` 管理后台，沿用 A 版雾白、墨黑与钴蓝。显示控制节点资源、在线中继集群总占用、每台节点的 CPU/内存/磁盘/网络速率、预留会话数、状态与最近上报时间。没有上报的节点显示离线，不填充示例资源数据。

**架构边界：一个信令控制节点 + 多台加密中继节点，不是多信令主节点集群。** CPU 按逻辑核心加权，内存和磁盘按字节汇总，离线节点排除并显示覆盖数量。资源来自 psutil 的主机可见口径，容器 CPU/内存配额不在该口径内。同一物理主机只部署一个采集节点，否则会重复计算。网络速率是收发总和，带宽预算也按收发合计设置，不是运营商带宽检测结果。

启动配置参考 `cluster-server.example.json`。控制节点启动进程通过 `NN_ADMIN_TOKEN` 接收至少 32 字符的高熵随机管理员令牌；不要使用设备令牌或 SSH 密码。`cluster_file` 指向专用可写目录中的节点登记文件，原子保存节点配置和节点令牌摘要，目录仅服务账号可写。Compose 已提供独立持久卷，TLS/设备登记仍挂载为只读。启用集群后禁用控制节点本地中继，避免满载时回退挤占控制节点。

通过可信 HTTPS 打开 `/admin`，输入管理员令牌，登记每台节点的名称、HTTPS 地址、会话容量和带宽预算。节点凭据只在登记成功时显示一次。节点地址必须是独立 HTTPS origin，不允许路径、查询参数或内嵌密码。登记不等于部署，不会使用 SSH 登录或安装远程程序。

每台节点参考 `relay-worker.example.json` 配置，使用独立 TLS 证书和专用非 root 账号，通过 `NN_NODE_TOKEN` 传入该节点凭据后运行：

```sh
python relay_worker.py --config /path/to/relay-worker.json
```

节点主动向控制端上报资源，不需要控制端持有节点 SSH 密码。客户端两端同时设置 `"relay": true, "cluster": true`。节点 HTTPS 证书须被客户端的 `signal_ca` 信任；推荐控制端与节点均使用客户端信任的公有 CA，或统一私有 CA 信任包。节点使用 `coordinator_ca` 验证控制端，始终开启证书验证。

调度行为：

- 先尝试端到端直连，中继只承担内层双向 TLS 密文；客户端向中继提交会话级票据，不发送长期设备令牌。
- 新中继会话在 CPU、内存、磁盘、网络预算与会话容量之间选择剩余容量较好的节点；同一会话双方固定到同一节点。等待配对也计入预留容量，避免并发超卖。
- 默认任一资源达到 90% 即停接新会话，所有资源低于 90% 时下一次采样即恢复。若手动设置更低的恢复水位，则仍需连续 3 次低水位采样。每轮通常 3 秒，超时可能延长。管理员可以调整阈值、容量或开启维护排空。
- 上报超过 15 秒未更新即判离线。全部节点满载或离线时返回 503，不绕过限额。已分配的会话不会因高水位或维护状态强制迁移。
- 节点故障时，已有会话会中断，需重新发起并由对端授权，新的会话再选择健康节点；不承诺无损热迁移。控制节点失败时，节点授权检查失败会关闭现有中继，不能维持未验证授权。
- 节点定期向控制端检查会话有效性；撤销后关闭连接，正常结束释放预留容量。登记配置跨重启保存，但设备在线状态、会话、票据和调度预留都在内存，控制端重启后需重新建连。

后台未部署到公网。公网部署还需域名、证书、节点配额、防火墙及握手/连接限速、日志与告警。它不包含 UDP 打洞、控制节点高可用、手机终端中继或远控会话热迁移。保留旧单节点模式兼容性；只启用 `relay` 而不启用 `cluster` 时行为不变。

第一阶段交付为 Python 信令服务与两个可交互的命令行参考客户端。设备经预登记后用 HTTPS 注册和刷新在线租约，发起端申请连接，被控端明确授权，双方以事先核验的设备证书建立双向 TLS 1.3 TCP 连接，完成一次二进制消息交换。项目独立实现业务代码，使用 aiohttp、Python 标准库 ssl（OpenSSL）以及用于生成测试证书的 cryptography。这些依赖提供通用网络与加密能力。

## 在一台机器上复现

安装 Python 3.12 及依赖后，在项目根目录生成仅用于本机测试的证书及令牌。需用三个终端。命令适用于 Bash。

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python provision_demo.py demo
python signal_server.py --config demo/server/config.json
```

在第二个终端启动接收端。

```sh
NN_DEVICE_TOKEN="$(cat demo/bob/token)" python peer.py --config demo/bob/config.json receive alice
```

在第三个终端发起连接。等接收端提示后，在其终端输入 `yes`，在邀请发出后 15 秒内确认。

```sh
NN_DEVICE_TOKEN="$(cat demo/alice/token)" python peer.py --config demo/alice/config.json send bob "你好，nn远程"
```

两个客户端分别打印收到的数据。信令端无需客户端私钥，也没有业务数据端口。测试证书由脚本即时生成，仅对生成目录内的客户端可用，有效期为七天。脚本要求使用全新的目录。

## 服务器部署

1. 在拟部署机器上安装容器运行环境，准备对应信令域名的 TLS 证书及私钥。复制 `server.example.json` 为运行目录内的 `config.json`。仅给连接双方签发高熵随机令牌，并分别私下交付。每个设备的令牌为 32 字节随机数的 64 个十六进制字符。用 `hashlib.sha256(token.encode()).hexdigest()` 计算登记值，把摘要和唯一设备 ID 填入 `devices`。信令进程可以读取摘要，无需读取客户端令牌文件。
2. 将包含 `config.json`、信令证书和私钥的绝对路径运行目录挂载到容器。确保只有管理员及容器运行账号（UID 10001）能读取信令私钥，且目录可遍历。以下命令用于先在本机检查 HTTPS，端口只发布到宿主机回环地址。

   ```sh
   docker build -t nn-remote-signal .
   docker run --rm --name nn-remote-signal \
     --read-only --cap-drop ALL --security-opt no-new-privileges \
     -p 127.0.0.1:8443:8443 \
     -v /absolute/private-runtime:/run/nn-remote:ro nn-remote-signal
   ```

   需要跨机器部署时，按所选服务器的网络配置绑定信令端口，并用防火墙限制参与测试的地址。如果在负载均衡、容器 NAT 或反向代理后运行，先验证信令进程看到的源地址与可连接的地址一致。服务选用实际 TCP 源地址，忽略转发头。状态放在单实例内存中，进程重启会使在线租约和邀请失效。
3. 两端配置各自私钥、证书和经独立可信渠道核验的对端证书。当前参考端使用自签名设备叶证书，SAN 为 `nn-peer`，客户端和服务端握手都验证证书，随后用 DER 精确匹配。根据证书和密钥分发流程保管私钥。信令使用单独的 TLS 证书，公有 CA 可把 `signal_ca` 设为 null。文件地址相对当前目录或使用绝对路径。设备换证要更新对端配置。可使用独立设备登记文件在运行时撤销设备，见部署小节。
4. 接收设备的 TCP 端口需能被发起端访问。若该端口经过路由器映射，当前参考端要求公开端口号与监听端口号相同。可在私有测试网络上先验证，不需要把任何设备开放到互联网。

## 协议及验证边界

- 信令使用 HTTPS 加设备令牌认证。只有在册设备可以注册，心跳租约 20 秒。邀请和授权各有 15 秒期限。只有被邀请的设备能批准、拒绝或在客户端核验证书后领取会话。领取后同一邀请不可再次使用。主动离线、租约到期或端点变更会删除关联会话。该版本只承载一次短消息，已建立的数据交换受自身读写超时约束。
- 控制面有 128 请求/秒全局限流、8 请求/秒每设备限流、4 KiB 请求体限制和有界会话数量。端点只给经明确批准的发起方。信令不向登记端点主动发包，不接受转发请求，默认不开启中继。客户端在身份、会话均验证后才回传，消息上限 64 KiB。部署到非私有网络前仍需补齐前置连接数和握手限额等部署控制。
- 当前交换 TCP 候选地址并尝试直连。UDP 打洞、ICE/STUN 及真实跨网成功率仍待验证；即使引入打洞也会受 NAT 类型、防火墙和拓扑限制。此版本无公网部署。
- 后续桌面流需将 30/60 帧选项应用到采集与编码目标并持久化，显示实际达到的帧率。固定码率下，60 帧通常意味着每帧分到的比特更少。同等画质通常需要更多带宽和编码资源。

## A 版桌面客户端

安装 Python 3.12、Tk 支持和依赖。Windows 安装包需包含 Tcl/Tk，macOS 可使用包含 Tk 的 Python 安装包。没有图形环境时可独立运行信令和手机终端。

```sh
python -m pip install -r requirements-desktop.txt
python desktop.py --config /path/to/peer-config.json
```

双击桌面程序或不带参数运行时，首次启动页会提示选择可信设备配置、核对 HTTPS 信令地址，并输入本机设备令牌。该入口不保存令牌，也不自动读取同目录的令牌文件。相对证书路径按配置文件所在目录解析。

使用上面的命令行方式时，通过 `NN_DEVICE_TOKEN` 环境变量传入令牌。本机演示可使用 `provision_demo.py demo` 产生的两个客户端配置。它们使用不同端口，可以各启动一个桌面窗口。设备列表只查询配置里已核验的设备 ID，在线和离线来自信令租约。窄窗口在列表与详情之间切换。

### 双向协助

在通讯录选中在线设备后，「协助对方电脑」向所选设备请求桌面连接。「请求对方协助」则邀请所选设备来帮助本机，需要本机已启用桌面共享能力（目前为 Windows）且信令服务和双方客户端都支持求助邀请。接受求助仅发送反向桌面请求；本机仍需单独确认共享模式，可以仅共享画面、允许操控或拒绝。未处理的求助邀请在 60 秒后过期。

### 互传文件

在对端在线时选中设备，点「发送文件」并选文件。接收方在 60 秒内选择接收目录并同意。两端校验证书，文件块经 TLS 1.3 直接传输。接收端校验文件长度和发送端提交的 SHA-256，刷盘并再次确认会话有效后才发布文件、返回 SHA-256，发起端匹配后显示成功。校验缺失、不一致、断线或取消时清理临时文件，不发布残缺文件。单文件上限 2 GiB，目标目录须支持硬链接（如 APFS、NTFS），同名文件会拒绝覆盖。目标监听端口必须能被发起端访问。启用可选中继时，直连无法建立会尝试改走中继。

文件传输使用 `file-v2` 握手，双方必须一起更新，不与第三阶段旧文件协议互通。发送端发现旧握手会在发送文件内容之前停止。若连接在接收端已发布文件、但发送端尚未收到确认时断开，发送端会报告失败，此时目标文件可能已完整存在；当前不自动重试或覆盖。

### 手机终端

在被控机安装并登录要使用的 Agent，把它的命令及工作目录放进 `terminal` 配置。Windows 通过 pywinpty 调用系统伪终端，Linux/macOS 使用系统 PTY。Windows 上如果 Agent 是 npm 生成的 `.cmd`，可显式配置为 `["cmd.exe", "/d", "/c", "codex.cmd"]`。也可直接启动已安装的可执行文件。PTY 开启后才启动一个新进程，手机断网或退出页面只断开连接；在桌面客户端里停止手机终端，或关闭被控端进程，会终止该会话。这个版本无法附着到在其他窗口里已启动的任意 Agent 进程。若需载入 Agent 以前保存的工作，请用该 Agent 自己的恢复命令作为启动参数。

安装 xterm.js 后可使用完整的 ANSI 终端。将其包目录配置为 `terminal.assets`。不装时网页提供简易文本模式，仍能发送输入，但不适合全屏终端 UI。

```sh
npm install --no-save @xterm/xterm@5.5.0
```

被控机直接提供 HTTPS/WSS。使用手机信任且主机名匹配的证书，选择手机能经私网访问的监听地址和端口。在被控端点击「开启手机终端」，手机访问窗口显示的地址并输入一次性配对码。配对后同一浏览器的会话凭据可重连；服务停止即撤销。首页的「连接 / 重连」会重新连接原进程，并回放最近 256 KiB 的输出。一次只允许一个终端连接。HTTPS 在被控机结束，不经过信令服务器或第三方终端中转；手机端依赖其浏览器的证书验证。

也可以从本机 CLI 显式启动，无需打开桌面客户端。以下为 Bash 示例，监听回环地址用于本机验证。

```sh
python terminal_portal.py --origin https://localhost:9446 \
  --cert /path/to/terminal-cert.pem --key /path/to/terminal-key.pem \
  --cwd /path/to/project --assets node_modules/@xterm/xterm -- codex
```

### Windows 桌面流

Windows 被控端可批准「仅共享画面」或「共享并允许操控」。共享期间本机有可见的停止窗口。当前采集主屏，使用有界 JPEG 帧和双向 TLS 1.3。设置中选 30 或 60 FPS 后持久保存，下次共享生效。查看窗口显示实际绘制帧数。FPS 是上限，受采集、编码、解码和带宽影响。当前逐帧独立编码，分辨率上限 1920×1080，单帧上限 512 KiB，复杂画面会降低 JPEG 质量以满足上限。固定每帧质量时，目标 60 帧会提高所需吞吐与 CPU。

输入使用 Windows SendInput。支持鼠标、基本按键和快捷键。安全桌面、管理员权限窗口、输入法和多显示器暂未验收。隐私屏与静音仍禁用。隐私验收需在真实 Windows 机器上证明物理屏持续显示隐私画面、远端操作隔离画面、被控端音频静音，并覆盖断开与崩溃恢复。当前没有安装 Windows 显示驱动或会话隔离后端。

### 私网部署与撤销

- 可用已有的私有虚拟网络或路由互通的局域网连接三类终端。信令进程看到的客户端地址必须是对端可达的地址。手机还需要能直接访问终端 HTTPS 地址并验证证书。手机终端没有公网中继。ICE/TURN、UDP 打洞和文件断点续传尚未实现。
- 桌面和文件可选用中继。在信令和两端客户端配置中都设置 `"relay": true`。先尝试直连。TCP 无法建立时通过同一个信令 HTTPS 地址建立授权 WebSocket 中继，对端身份仍由内层双向 TLS 校验。证书验证失败时直接报错。中继要求有效邀请和两端角色，有并发及速率上限，只传内层 TLS 密文。当前只做了云端模拟不可达端口测试，仍需用两条真实宽带、蜂窝网和防火墙实测。
- 可在信令配置中用 `"registry_file": "/run/nn-remote/registry.json"` 指定独立登记文件，结构参考 `registry.example.json`。在同一目录生成新文件并用原子替换提交注册、轮换或删除。缺失或格式错误会暂停登记访问。成功撤销后，活跃桌面和文件连接会在下一次授权轮询时断开。默认登记刷新间隔 1 秒，双端每 2 秒检查会话，信令检查超时为 2 秒。桌面客户端侦测到本机令牌被拒绝会关闭其开启的终端服务，独立运行的手机终端由本机停止或在配对后 8 小时到期。
- 用 `python signal_server.py --config /path/to/config.json --check` 校验服务器配置是否可加载。Compose 示例默认只发布宿主机回环端口，填写 `NN_SIGNAL_RUNTIME` 和 `NN_SIGNAL_CERT_NAME` 后可运行 `docker compose up -d --build`。信令域名探针用正常 TLS 校验访问 `/healthz`。使用私有 CA 时，另设指向容器内 CA 证书的 `NN_SIGNAL_HEALTH_CA`。
- 云端新增的测试使用合成桌面帧和记录式输入，端到端验证设备授权、帧传输、输入协议、撤销后释放输入。文件中断与撤销在发布前会清理临时文件。Docker 镜像、Windows 桌面后端、真机互传、移动浏览器与公网仍待验证。已提供手动触发的 macOS/Windows 未签名测试包构建工作流，未在托管 runner 执行。签名安装程序、自动更新和多实例运维不包含在此包。
